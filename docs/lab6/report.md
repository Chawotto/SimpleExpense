


# Отчет по Лабораторной работе №6

---

## 1. Введение и цели работы
Целью данной лабораторной работы является качественный аудит и последующий рефакторинг пользовательского интерфейса (UI) и пользовательского опыта (UX) приложения **FinanceFlow Ultra**. Работа опирается на международные стандарты (ISO/IEC 25010:2011), спецификации доступности (WCAG 2.0) и принципы многоуровневого проектирования опыта использования.

Переход от функционального MVP к полноценному продукту требует фокуса на эмпатии к пользователю, минимизации когнитивной нагрузки и предотвращении критических ошибок.

---

## 2. Оценка разрабатываемого ПО по атрибутам качества «Usability» (ISO/IEC 25010:2011)

До проведения работ по улучшению, приложение было проанализировано по шести ключевым атрибутам качества группы Usability (SQuaRE):

1.  **Распознаваемость соответствия (Appropriateness recognizability) — 5/5**
    *   *Оценка:* Пользователь с первых секунд понимает назначение продукта. Использование общепринятых паттернов (зеленый цвет для доходов, красный/нейтральный для расходов), иконки кошелька, монет и графиков-бубликов формируют четкую ментальную модель финансового трекера.
2.  **Обучаемость (Learnability) — 3/5 (ДО) ➔ 5/5 (ПОСЛЕ)**
    *   *Проблема:* Раздел «Мои цели» при отсутствии записей оставался абсолютно пустым. Это нарушало принципы Onboarding-а: новый пользователь не понимал, должен ли здесь появиться контент автоматически или требуются его действия.
    *   *Решение:* Внедрение паттерна «Empty State» (Пустое состояние) с четким призывом к действию (Call-to-Action).
3.  **Используемость / Операбельность (Operability) — 3/5 (ДО) ➔ 5/5 (ПОСЛЕ)**
    *   *Проблема:* Навигация базировалась исключительно на использовании мыши (Point-and-Click).
    *   *Решение:* Реализована поддержка клавиатурной навигации (клавиша `Tab`) и переключение радио-кнопок (Доход/Расход) клавишей `Enter`.
4.  **Защита от ошибок пользователя (User error protection) — 2/5 (ДО) ➔ 5/5 (ПОСЛЕ)**
    *   *Проблема:* Критический антипаттерн в проектировании форм и действий. Удаление финансовой транзакции вызывало системный браузерный алерт `window.confirm()`. Пользователь мог случайно нажать пробел или Enter и безвозвратно уничтожить данные без возможности восстановления.
    *   *Решение:* Разработка кастомного модального окна с блокировкой фона (Overlay) и явным разделением кнопок (безопасная «Отмена» и деструктивная красная «Удалить»).
5.  **Эстетика GUI (User interface aesthetics) — 4/5 (ДО) ➔ 5/5 (ПОСЛЕ)**
    *   *Оценка:* Приложение выполнено в современном стиле Glassmorphism (размытие фона, градиенты, полупрозрачные карточки). Эстетика была нарушена лишь нативным окном подтверждения, что было исправлено в ходе ЛР.
6.  **Доступность (Accessibility / WCAG 2.0) — 1/5 (ДО) ➔ 5/5 (ПОСЛЕ)**
    *   *Проблема:* Кнопки смены темы, выхода из профиля, редактирования и удаления состояли исключительно из иконок FontAwesome. Программы экранного доступа (Screen Readers) озвучивали их как «Пустая кнопка».
    *   *Решение:* Внедрение атрибутов `aria-label` и `role="dialog"` для всех интерактивных элементов интерфейса.

## 3. Декомпозиция по уровням «Опыта использования» (Jesse James Garrett's 5 Elements of UX)

Архитектура UX FinanceFlow Ultra была проанализирована на пяти абстрактных уровнях:

### Уровень 1: Стратегии (Strategy)
*   **Потребности пользователей:** Быстро зафиксировать трату на ходу (с мобильного или ПК), понять общую картину расходов за месяц, отложить деньги на крупную покупку.
*   **Бизнес-цели:** Вовлечение пользователя (Retention) за счет геймификации (заполнение прогресс-баров целей) и эстетического удовольствия от использования продукта.

### Уровень 2: Набора возможностей (Scope)
*   **Функционал:** Авторизация OAuth 2.0 (Google), агрегация баланса, мультивалютность (RUB, BYN, USD, EUR), добавление/удаление/редактирование (CRUD) транзакций, визуализация через Chart.js, управление финансовыми целями, темная/светлая тема.

### Уровень 3: Структуры (Structure)
*   **Информационная архитектура:** Модель Single Page Application (SPA). Маршрутизация сведена к минимуму: экран входа (Auth) линейно переходит в единый Дашборд (Dashboard), где все функции доступны в один клик. Отсутствие глубокой иерархии страниц снижает показатель Interaction Cost (стоимость взаимодействия).

### Уровень 4: Компоновки (Skeleton)
*   **Расположение элементов (Wireframing):** 
    *   *Header:* Идентификация пользователя и глобальные настройки (валюта, тема, выход).
    *   *Hero Section:* Ключевая метрика (Общий баланс) и виджеты трендов (Доход/Расход).
    *   *Sidebar/Middle:* Модуль целей и визуальная аналитика (График).
    *   *Main Action Area:* Форма ввода (всегда под рукой).
    *   *Footer/List:* Журнал истории с группировкой по датам.

### Уровень 5: Поверхности (Surface)
*   **Визуальный дизайн:** Цветовая палитра основана на контрастных акцентах (Indigo, Emerald, Rose) поверх нейтрального фона (Slate/Gray). Использован шрифт *Plus Jakarta Sans* для идеальной читаемости цифр. Эффект матового стекла создает иллюзию глубины (Z-axis).

## 4. Обоснование и реализация UX-улучшений («ДО» vs «ПОСЛЕ»)

В рамках лабораторной работы был проведен рефакторинг трех ключевых проблемных зон.

### Улучшение №1: Защита от деструктивных действий (Custom Confirm Modal)
*   **Необходимость:** Системные окна `confirm` в браузерах Chrome/Safari выглядят по-разному, блокируют основной поток выполнения (Main Thread) и не позволяют стилизовать кнопки. Это нарушает целостность пользовательского опыта.
*   **Реализация:** Создано DOM-окно с атрибутами `aria-modal="true"`.
*   **ДО:** Стандартное серое всплывающее окно браузера с текстом «Удалить?».
*   **ПОСЛЕ:** Кастомное диалоговое окно в стиле Glassmorphism. Кнопка «Отмена» имеет нейтральный стиль (Secondary Button), а кнопка «Удалить» залита акцентным красным цветом (Danger Zone). Добавлена предупреждающая иконка и текст «Это действие нельзя отменить».

### Улучшение №2: Внедрение Onboarding через Empty States
*   **Необходимость:** Пустой экран вызывает у пользователя чувство фрустрации (эффект чистого листа). Интерфейс должен подсказывать следующий шаг.
*   **Реализация:** Написана логика в `app.js`, которая проверяет длину массива `goalsData`. Если длина равна `0`, контейнер с целями скрывается, а блок `goals-empty-state` отображается.
*   **ДО:** Под заголовком «Мои цели» находилось пустое прозрачное пространство.
*   **ПОСЛЕ:** Отображается блок с пунктирной рамкой и микрокопирайтингом: *"У вас пока нет финансовых целей. Нажмите "+", чтобы создать"*. Дополнительное улучшение: при клике на кнопку "+", курсор автоматически устанавливается в поле ввода (`focus()`), избавляя пользователя от лишнего клика.

### Улучшение №3: Соответствие стандарту доступности WCAG 2.0
*   **Необходимость:** Продукт должен быть доступен для людей с нарушениями зрения или моторики, использующих скринридеры (VoiceOver, NVDA) и клавиатуру.
*   **Реализация:** 
    *   Добавлены свойства `aria-label="..."` ко всем иконочным кнопкам.
    *   В CSS добавлен псевдокласс `:focus-visible`, который создает яркое свечение (Glow-эффект) вокруг элемента, на который переведен фокус клавишей `Tab`.
*   **ДО:** Нажатие клавиши `Tab` не давало визуального отклика (фокус скрывался браузером), кнопки не озвучивались скринридером.
*   **ПОСЛЕ:** Четкий контур фокуса (Outline) вокруг активных элементов. Скринридер корректно читает: *"Переключить тему, кнопка"*, *"Удалить транзакцию, кнопка"*.

## 6. Выводы

В ходе выполнения Лабораторной работы №6 был успешно проведен полный цикл улучшения UX продукта FinanceFlow Ultra. Приложение было оценено по международным стандартам ISO/IEC 25010:2011, что позволило выявить критические недочеты в области защиты от ошибок, обучаемости и доступности.

В результате внедрения кастомных диалоговых окон, состояний «Empty State» и полной поддержки клавиатурной навигации по стандарту WCAG 2.0, юзабилити системы выросло до максимальных показателей. Приложение стало более безопасным, интуитивно понятным и инклюзивным. Трассируемость изменений была строго задокументирована через GitHub Projects, что подтверждает соответствие команды процессам профессиональной разработки ПО.
